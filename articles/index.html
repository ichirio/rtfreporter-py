    Articles¶

    Practical guides for producing clinical RTF deliverables. Start with Get started, then work through the guides below in roughly this order.

    For package users¶

    • Document API guide

      The two equivalent ways to build a document — the R-style functional calls and the fluent method chain — and when each reads better.

    • Page and document setup

      Paper size, orientation, margins, the header/footer band, fonts, and the rtfreporter.* option defaults.

    • Adding tables and figures

      Putting content on pages: rtf_tables(), rtf_figures(), per-page titles and footnotes, one content item per page.

    • Borders and rules

      The TFL border convention, the five zones, and per-column and per-cell overrides.

    • Importing tables

      as_rtftable() / as_rtftables() for pandas, polars and great_tables, and exactly what metadata is carried across.

    • Paginating

      Split strategies, group-aware breaks, (Cont.) continuation markers and widow/orphan control.

    • Headers and footers

      Sections, running headers and footers, and the automatic page-number fields.

    • Splitting a report into sections

      One section per group or per table, and combine_sections().

    • Post-hoc styling

      Restyling a finished table with style_header(), style_body(), style_cols() and style_zone().

    • Figures

      Embedding PNG and JPEG at native DPI.

    • Rendering and post-processing

      generate_rtfreport(), what the bytes look like, and last-mile edits with rtf_replace_text().

    • Assembling deliverables

      Combining several RTF files into one document with a table of contents.

    Worked clinical examples¶

    End-to-end recipes whose figures are checked against the R implementation.

    • Demographics (Table 14.1.1)

      A production-style demographics table from real ADaM data, built both from a pandas DataFrame and from a great_tables object.

    • Adverse events by SOC/PT

      Subjects with treatment-emergent adverse events by system organ class and preferred term: independent SOC counts, a 3% filter, and multi-page output with (Cont.).

    Relationship to the R package¶

    • Relationship to R

      How this port is developed — features land in R first — where to ask questions, and where the two packages necessarily differ.

    • Differences from the R package

      The two deliberate divergences: 0-based indices and the blank_rows sentinels.
